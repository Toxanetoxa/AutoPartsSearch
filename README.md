# Поиск автозапчастей

Одностраничное React-приложение для поиска автозапчастей по артикулу через API **Favorit Parts**. Пользователь вводит номер детали, выбирает производителя и получает предложения оригинальной детали и её аналогов с ценами и остатками на конкретных складах.

Приложение написано на **JavaScript и JSX**. Запросы выполняются из браузера напрямую в Favorit Parts. Для работы нужны Node.js, npm и ключ API; отдельный сервер приложения и база данных не требуются. Результат сборки — статические файлы в каталоге `dist/`.

## Возможности

- Поиск производителей по артикулу с автоматическим запросом после паузы во вводе.
- Немедленный поиск по кнопке «Найти» или клавише Enter.
- Выбор производителя и загрузка оригинальной детали вместе с аналогами.
- Отображение названия, бренда, артикула, склада, складского остатка и цены.
- Обозначение оригиналов, аналогов, отсутствия остатка и ограничений возврата.
- Сохранение артикула в адресной строке и восстановление после перезагрузки.
- Таблица на больших экранах и отдельные карточки на мобильных устройствах и планшетах.
- Прокрутка результатов внутри панелей и постраничный вывод по 50 предложений.
- Валидация поля, индикаторы загрузки, состояния пустого результата, сообщения об ошибках и ручной повтор запроса.
- Управление формой и выбором производителя с клавиатуры, доступные подписи полей и областей результатов.

## Установка и запуск

### 1. Установить инструменты

Требуются **Node.js 22.12.0 или новее** и **npm**. В `package.json` указан менеджер пакетов `npm@11.18.0`. Vite и остальные инструменты устанавливаются как зависимости проекта; глобально устанавливать их не нужно.

Проверьте доступность команд:

```sh
node --version
npm --version
```

### 2. Установить зависимости

Откройте терминал в корне проекта и выполните:

```sh
npm ci
```

Команда устанавливает зависимости по `package-lock.json`. Для первой установки нужен доступ к npm registry.

### 3. Настроить Favorit Parts

Если файла `.env` ещё нет, скопируйте шаблон:

```sh
cp .env.example .env
```

В PowerShell можно использовать `Copy-Item .env.example .env`. Если `.env` уже существует, отредактируйте его, сохранив текущие настройки.

Укажите базовый адрес API и полученный у Favorit Parts ключ:

```dotenv
VITE_FAVORIT_API_KEY=ваш_ключ
VITE_FAVORIT_API_URL=https://api.favorit-parts.ru
```

Обе переменные обязательны. `VITE_FAVORIT_API_URL` задаёт абсолютный базовый HTTP(S)-адрес без query-параметров, hash, логина и пароля. Путь `/hs/hsprice/` клиент добавляет сам; при наличии префикса пути в базовом адресе он сохраняется. Не добавляйте `/hs/hsprice/` в значение повторно.

При отсутствии ключа или пустом либо некорректном адресе приложение показывает подсказку о настройке и не отправляет запросы. Тестовые примеры не подставляются вместо ответа API.

**Ключ доступен в браузере.** Vite включает переменные с префиксом `VITE_` в клиентскую сборку; ключ также передаётся в query-параметре запроса к API. Используйте ключ, предназначенный для такого доступа. Файлы `.env` и `.env.*` исключены из Git, кроме публичного шаблона `.env.example`.

### 4. Запустить приложение

```sh
npm run dev
```

Откройте [http://127.0.0.1:5173](http://127.0.0.1:5173). Команда `npm start` запускает тот же сервер разработки.

Сервер привязан к `127.0.0.1`. Порт `5173` фиксирован: если он занят, Vite сообщит об ошибке вместо выбора другого порта. После изменения `.env` перезапустите сервер разработки. Для изменения ключа или адреса API в собранном приложении потребуется повторная сборка.

## Как работает поиск

1. Пользователь вводит артикул. Поле проходит валидацию, а его значение сразу сохраняется в URL.
2. Через **450 мс** после последнего изменения корректного артикула отправляется запрос производителей. Кнопка «Найти» и Enter запускают поиск сразу, без ожидания debounce.
3. Ответ API проверяется схемой Zod и преобразуется в список уникальных производителей.
4. Пользователь выбирает производителя. Приложение запрашивает предложения этого бренда с включёнными аналогами.
5. Полученные товары и вложенные аналоги преобразуются в единый список складских предложений. На странице показывается до **50** предложений.

При изменении артикула прежний выбор производителя и предложения сразу скрываются. Устаревшие запросы отменяются, чтобы их запоздавшие ответы не заменили текущий результат. Повторный поиск по кнопке для того же артикула обновляет производителей и сбрасывает выбранный бренд.

Для обоих этапов предусмотрены состояния загрузки, ошибки и пустого ответа. Ошибку можно повторить кнопкой «Попробовать снова»; автоматические повторы не выполняются.

### Валидация артикула

- После удаления пробелов по краям артикул должен содержать от **1 до 80 символов**.
- Управляющие символы не допускаются.
- Регистр, Unicode и значимая пунктуация сохраняются: например, `/`, `#`, `&`, дефисы и пробелы внутри номера.
- Некорректное или пустое значение не отправляется в API.

## Артикул в URL

Поисковое поле связано с query-параметром **`number`**:

```text
http://127.0.0.1:5173/?number=01089
```

При открытии такой ссылки или перезагрузке страницы поле восстанавливается, а для корректного артикула автоматически загружаются производители, если настроен ключ API.

Поведение реализовано в [useSearchNumber.js](src/hooks/useSearchNumber.js):

- Ввод обновляет текущую запись истории через `history.replaceState`, без перезагрузки и создания записи на каждый символ.
- `URLSearchParams` кодирует специальные символы; в поле сохраняется введённое значение, а для запроса удаляются только внешние пробелы.
- Очистка поля удаляет `number`, сохраняя путь, остальные query-параметры и hash.
- Событие `popstate` синхронизирует поле при переходах по истории браузера и сбрасывает прежний выбор производителя.

В URL сохраняется **только артикул**. Выбранный бренд, страница предложений и кэш ответов не восстанавливаются после перезагрузки. Для этого механизма не требуются маршрутизатор или `localStorage`.

## Адаптивный интерфейс

| Ширина окна              | Производители                        | Предложения и аналоги                      |
| ------------------------ | ------------------------------------ | ------------------------------------------ |
| Больше `1080px`          | Вертикальный список слева            | Таблица справа с закреплёнными заголовками |
| До `1080px` включительно | Горизонтальная лента карточек сверху | Вертикальный список карточек снизу         |

Мобильное представление использует отдельные компоненты карточек. Одновременно выводится только подходящее представление результатов. При изменении ширины сохраняются выбранный производитель, данные и текущая страница; дополнительный API-запрос не требуется.

Приложение занимает высоту окна с помощью `100dvh`. Производители и предложения прокручиваются внутри своих панелей. Кнопки пагинации находятся вне области прокрутки результатов; переход на другую страницу возвращает её прокрутку к началу. При высоте окна до `480px` предусмотрена дополнительная прокрутка внутри приложения, чтобы форма и кнопки оставались доступны.

Порог переключения задан в [useMediaQuery.js](src/hooks/useMediaQuery.js) и соответствующих CSS media queries. При его изменении нужно синхронно обновить JavaScript, стили и тесты.

## Архитектура и состояние

Поток данных разделён на несколько небольших слоёв:

```text
Форма и выбор бренда (App)
          ↓
Хуки RTK Query (api/queries.js)
          ↓
Fetch + проверка JSON (api/client.js)
          ↓
Преобразование товаров (domain/parts.js)
          ↓
Кэш Redux → производители, таблица или карточки
```

**Локальное состояние React** хранит выбранный бренд, состояние валидации, принудительно отправленный артикул и текущую страницу предложений. Сам артикул хранится в состоянии хука `useSearchNumber` и синхронизируется с адресом страницы.

**Redux store** содержит состояние RTK Query: данные, ошибки, статусы загрузки и кэш запросов. Для производителей используется ключ по артикулу, для предложений — по паре «артикул + бренд». Отдельный Redux slice для формы не нужен: её состояние используется локально.

**Доменный слой** не зависит от компонентов и сети. Он проверяет структуру данных, выделяет производителей, разворачивает аналоги и формирует складские предложения. Эти преобразования можно тестировать отдельно от React.

### Кэш и отмена запросов

- Результат хранится в памяти Redux и может переиспользоваться при возвращении к тому же артикулу или бренду.
- После удаления последней подписки неиспользуемые данные сохраняются ещё **60 секунд**.
- При новой подписке или смене аргумента результат старше **60 секунд** запрашивается повторно. Периодического обновления по таймеру нет.
- Автоматические повторы, обновление при фокусе окна и восстановлении соединения отключены. Пользователь может обновить данные вручную.
- При смене аргументов и размонтировании отменяются незавершённые устаревшие запросы. Очистка эффектов в React StrictMode не отменяет актуальный запрос.
- До выбора бренда запрос предложений не выполняется. При отсутствии ключа, некорректном базовом URL или некорректном артикуле оба этапа пропускаются.

## Работа с API

Базовый адрес берётся из `VITE_FAVORIT_API_URL` в [src/api/config.js](src/api/config.js). [Клиент](src/api/client.js) использует сформированный endpoint:

```text
GET {VITE_FAVORIT_API_URL}/hs/hsprice/
```

Для сервиса из [документации Favorit Parts](https://lk.favorit-parts.ru/static/wsprice.pdf?v=060223) используйте домен **`api.favorit-parts.ru`**. Для GitHub Pages задайте HTTPS-адрес `https://api.favorit-parts.ru`. Домен `api.favorit.ru` не соответствует адресу этого сервиса в документации.

Оба этапа используют один endpoint с разными параметрами:

| Параметр    | Производители                  | Предложения             |
| ----------- | ------------------------------ | ----------------------- |
| `key`       | Ключ из `VITE_FAVORIT_API_KEY` | Тот же ключ             |
| `number`    | Артикул                        | Артикул                 |
| `info`      | `on`                           | `on`                    |
| `brand`     | Не передаётся                  | Выбранный производитель |
| `analogues` | Не передаётся                  | `on`                    |

Параметры формируются через `URLSearchParams`, чтобы специальные символы в артикуле или бренде не меняли структуру запроса. Запросы отправляются без cookies (`credentials: 'omit'`).

Клиент принимает ответы с массивом `goods` или сообщением `error`. Ответ проверяется Zod-схемой, включая склады и вложенные аналоги. Ошибка сервиса обрабатывается даже при **HTTP 200**. Также предусмотрены сообщения для неверного ключа, превышения квоты, сетевой ошибки, некорректного JSON и неизвестного формата данных.

Схема проверяет обязательные поля исходного ответа, в том числе `goods.price`, даже если часть полей не участвует в отображении. Цены и остатки должны быть числами; строковые значения не приводятся автоматически.

Ожидание ограничено **15 секундами**, включая чтение JSON-тела ответа. Таймаут и отмена используют `AbortController`. Произвольный текст ошибки внешнего сервиса не выводится пользователю: сообщения формируются в [errors.js](src/api/errors.js).

### CORS и протокол размещения

Для прямого обращения из браузера API должен разрешать CORS для origin приложения. Это настройка внешнего API; изменить её в клиентском коде нельзя.

Для GitHub Pages задавайте в `VITE_FAVORIT_API_URL` адрес по **HTTPS**: браузер блокирует HTTP-запросы со страницы HTTPS как mixed content. У выбранного сервиса должны быть корректный TLS-сертификат, совместимый endpoint `/hs/hsprice/` и подходящий CORS. Изменение переменной переключает адрес, но не меняет контракт запросов и ответов Favorit Parts.

## Правила обработки данных

Преобразования реализованы в [src/domain/parts.js](src/domain/parts.js).

### Производители

- Список строится из товаров верхнего уровня ответа `goods`.
- Повторяющиеся бренды объединяются без учёта регистра и внешних пробелов; для отображения сохраняется написание первого найденного бренда.
- Техническая запись с нулевым `goodsID` и записи с пустым брендом пропускаются.
- Реальная деталь без остатка остаётся в списке: её производитель доступен для выбора.
- Бренды, встречающиеся только во вложенных аналогах, не добавляются к первому этапу поиска.

### Складские предложения

- Вложенные `analogues` разворачиваются рекурсивно. Оригинальные товары сохраняют приоритет при объединении повторов.
- Повторяющиеся товары объединяются, их складские предложения дополняются. Идентичные предложения не дублируются, а отличающиеся ценой, остатком или данными отгрузки сохраняются отдельно.
- Одна строка таблицы или одна карточка соответствует **конкретному складскому предложению**.
- Цена берётся из **`warehouses[].price`**, остаток — из **`warehouses[].stock`**. Общее `count` и устаревшее `goods.price` не подставляются вместо складских значений.
- Если складов нет, товар показывается с нулевым остатком, отметкой «Нет в наличии» и прочерком вместо цены.
- Нулевая цена и нулевой остаток — допустимые значения; они не означают отсутствие данных.
- Ограничение `notRefund` учитывается и на уровне товара, и на уровне склада. Интерфейс показывает текст «Без возврата по причине “Отказ”».
- Для склада используется `code`, а при его отсутствии — `id`. Цена форматируется в рублях с двумя знаками после запятой.

Счётчик «В наличии» показывает количество складских предложений с положительным остатком, а не сумму единиц товара. Пагинация выполняется **на клиенте** после получения полного ответа API. При смене артикула или бренда вывод начинается с первой страницы.

## Тестирование и качество кода

Тесты работают в **Vitest + jsdom**, взаимодействия с интерфейсом проверяются через **React Testing Library** и `user-event`. Реальные HTTP-запросы заменены управляемыми ответами; для запуска тестов рабочий ключ API не нужен.

Покрываются следующие уровни:

| Область          | Основные сценарии                                                                                                              |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Доменные функции | Валидация, структура ответа, производители, вложенные аналоги, дубликаты, складские цены, остатки и ограничения возврата       |
| API-клиент       | Параметры URL, кодирование, HTTP-ошибки и ошибки при HTTP 200, неверный JSON, таймаут, отмена запроса                          |
| RTK Query        | Условия запуска, независимые ключи кэша, переиспользование и обновление результатов, отмена устаревших запросов, ручной повтор |
| Хуки             | Debounce, подписка на media query, синхронизация с URL, история браузера и очистка подписок                                    |
| Компоненты       | Выбор производителя, таблица, мобильные карточки, пагинация, смена представления и сброс прокрутки                             |
| Приложение       | Полный сценарий поиска, загрузка, ошибки, пустые результаты, сброс старых данных и восстановление артикула                     |

Для быстрой проверки:

```sh
npm test
```

Для отчёта о покрытии:

```sh
npm run test:coverage
```

Пороги в `vite.config.js`: **80% строк, выражений и функций**, **75% веток**. При недостаточном покрытии команда завершается с ошибкой. HTML-отчёт создаётся в `coverage/index.html`, также формируются текстовый отчёт и `coverage/lcov.info`.

Для полной проверки перед передачей изменений:

```sh
npm run check
```

Эта же команда запускается в [GitHub Actions](.github/workflows/ci.yml) после `npm ci` на Node.js 22. Тесты в jsdom проверяют поведение компонентов; геометрию, внешний вид и прокрутку на реальных устройствах дополнительно проверяют в браузере.

Во всех заданиях CI закреплён runner `ubuntu-24.04`, чтобы переход `ubuntu-latest` на другой выпуск Ubuntu не менял среду сборки. Сами действия GitHub используют runtime Node.js 24; команды npm для проекта выполняются на Node.js 22, выбранном через `setup-node`.

## Сборка и размещение

```sh
npm run build
npm run preview
```

`build` создаёт оптимизированные статические файлы в `dist/`. `preview` запускает локальный сервер для просмотра готовой сборки; адрес будет указан в терминале. Перед `preview` нужно выполнить сборку, а после изменения кода или ключа — повторить её.

Для размещения достаточно загрузить содержимое `dist/` на статический хостинг. Node.js на хостинге для исполнения приложения не требуется. Ключ и базовый URL нужно задать **до сборки** в окружении, где выполняется `npm run build`: изменение `.env` рядом с уже готовыми статическими файлами не изменит приложение.

При выборе хостинга учитывайте CORS внешнего API, описанный в разделе [«Работа с API»](#работа-с-api).

### GitHub Pages

Публикация настроена в [`.github/workflows/ci.yml`](.github/workflows/ci.yml). После успешных проверок push в основную ветку запускает сборку и деплой. Pull request и остальные ветки проходят проверки без публикации. Workflow также можно запустить вручную через **Actions → Checks → Run workflow** на основной ветке.

Для репозитория `Toxanetoxa/AutoPartsSearch` ожидаемый адрес сайта:

```text
https://toxanetoxa.github.io/AutoPartsSearch/
```

Первичная настройка в GitHub:

1. Откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**.
2. В **Settings → Secrets and variables → Actions → New repository secret** создайте секрет `VITE_FAVORIT_API_KEY` со значением ключа Favorit Parts.
3. Там же создайте repository secret `VITE_FAVORIT_API_URL` со значением `https://api.favorit-parts.ru` или другим совместимым базовым адресом API. Адрес также можно задать на вкладке **Variables → New repository variable**; если заданы оба варианта, используется secret.
4. Отправьте изменения workflow в основную ветку или запустите его вручную. Вкладка **Actions** покажет результат проверок, сборки и деплоя.
5. Откройте адрес из шага деплоя или раздела **Settings → Pages**.

В поле **Name** указывайте название настройки, а в поле **Secret** или **Value** — только её значение, без `VITE_FAVORIT_API_KEY=` или `VITE_FAVORIT_API_URL=`, кавычек и обратных слешей. Для URL значение выглядит как `https://api.favorit-parts.ru`.

Локальный `.env` в GitHub не отправляется: при публикации ключ передаётся из repository secret, а базовый адрес — из repository secret или, при его отсутствии, repository variable в шаг сборки. После изменения любой настройки запустите полный workflow заново для пересборки. Повтор одного задания деплоя использует прежний артефакт и не добавляет новые настройки. При отсутствии настройки интерфейс опубликуется, но покажет сообщение об ошибке конфигурации и не будет отправлять запросы.

Секрет защищает хранение ключа в настройках и логах GitHub, однако **в готовом приложении ключ остаётся доступен браузеру**, как и при локальной сборке.

Путь Vite `base` берётся из `actions/configure-pages` и передаётся в команду сборки. Для этого репозитория он равен `/AutoPartsSearch/`, поэтому JavaScript и CSS загружаются из правильного подкаталога. Локальные `npm run dev` и `npm run build` продолжают использовать корневой путь `/`.

Проверить такую сборку локально можно командами:

```sh
npm run build -- --base=/AutoPartsSearch/
npm run preview -- --base=/AutoPartsSearch/
```

В preview откройте `/AutoPartsSearch/` на адресе, указанном Vite. Общие инструкции: [GitHub Pages с Actions](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages), [публикация Vite](https://vite.dev/guide/static-deploy#github-pages).

## Частые вопросы при запуске

| Ситуация                                               | Что проверить                                                                                                                                                                                         |
| ------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Появилось сообщение «Не настроен API Favorit Parts»    | В `.env` заданы `VITE_FAVORIT_API_KEY` и корректный `VITE_FAVORIT_API_URL`; Vite перезапущен. Для Pages проверьте repository secrets (для URL также подходит variable), затем пересоберите приложение |
| Ключ не принят                                         | Корректность и доступность ключа у Favorit Parts; после изменения ключа перезапустите разработку или пересоберите приложение                                                                          |
| Превышен лимит запросов                                | Дождитесь восстановления квоты API и повторите поиск вручную                                                                                                                                          |
| Нет соединения с API                                   | Доступность HTTPS endpoint, корректность сертификата API и CORS для текущего origin                                                                                                                   |
| Порт `5173` занят                                      | Освободите порт или измените `server.port` в `vite.config.js`                                                                                                                                         |
| После перезагрузки артикул есть, а предложения исчезли | Сохраняется только `number`; после загрузки производителей выберите бренд повторно                                                                                                                    |
| Не найдены производители или предложения               | Проверьте артикул; пустой ответ отображается отдельно от ошибки соединения                                                                                                                            |
| Не проходит проверка форматирования                    | Выполните `npm run format`, затем повторите `npm run check`                                                                                                                                           |
